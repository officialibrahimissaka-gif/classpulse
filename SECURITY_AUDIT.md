# Phase 6 security audit

**Release decision: NOT PRODUCTION READY / NO-GO.** Baseline `1c22cb0`, audited 1 November 2026. This is a fresh adversarial review of the implementation by the same assistant, not a third-party attestation. Automated findings below were remediated locally; essential production assurance and functional gaps remain open. No deployment or main-branch change is authorized by this report.

## Scope, method and evidence

Native PostgreSQL 17 with restricted runtime/maintenance identities; Redis/BullMQ; actual HTTP routes and browser rendering; synthetic owner/recruiter/entity/client actors in separate tenants; private local artifacts; Mailpit only. Read approved R1, security/threat, entitlement and workflow contracts and inspected route/use-case/worker/maintenance paths. Existing suite first passed with 21 tests; new secure expectations then exposed defects. Retain [pre-fix reproduction summaries](docs/quality/phase6/reproduction-summary.json), target retests and final gate logs under docs/quality/phase6.

Only local loopback targets may be used by the automated harness; tests now refuse production/non-loopback configurations. Real OIDC, SES, S3/KMS, managed PostgreSQL backups, ingress/WAF and deployment IAM were not available. No customer data, actual customer recipients or third-party systems were attacked.

## Test-category disposition

- **Cross-tenant/BOLA/escalation:** native restricted-role and real-route negative tests PASS for exercised records; entity/participant defects above fixed. GUC-based RLS supplements application predicates and cannot contain a fully compromised runtime choosing another tenant context.
- **Sensitive data/files:** restricted projections, ownership/scope/expiry/integrity checks, private proxy access, CSV formula safety, literal XLSX cells and SQL/XSS-as-data tests pass locally. Real bucket policies/KMS/transfers remain blocked.
- **Sessions/authentication:** tampered cookie, Origin/CSRF, membership revision/revocation, logout cookie clearing, production-config failure tests pass. Provider login/MFA/device/federation/global logout have not been live-tested.
- **Rate limits:** Redis enforcement and untrusted-header resistance pass. TRUST_INGRESS_IP must stay false until a private ingress overwrite contract is independently verified. Distributed/edge abuse and Redis outage chaos tests are not certified.
- **Injection:** typed parameterized SQL and real literal SQL/HTML payloads pass; unknown ownership/salary fields are rejected. This is not an exhaustive penetration test of every parser/provider.
- **Webhooks:** no public webhook ingestion or payment connector exists. Authenticated unsupported webhook/payment routes return 404. Signature verification/replay claims are N/A, not passed.
- **Audit:** immutable application DB rows, business events/export/download and added privileged-read/denial metadata have local evidence. Full operational/authentication audit completeness and external tamper evidence remain P6-B05.

No production readiness declaration, deployment, financial certification or legal compliance certification is issued.

## P6-G06 — Development dependency advisory

**Medium / OPEN — build-tool owner.** An additional full-tree `npm audit --json` reports 16 moderate affected dependency nodes in the ESLint/Next/TypeScript lint toolchain, rooted in minimatch globparts-amplification denial of service. The production-only gate reports zero vulnerabilities. This is a build/development exposure when processing hostile patterns or repository inputs; it is not evidence of a public runtime exploit. Restrict CI to trusted inputs and bounded jobs pending a compatible upstream patch; investigate and retest the complete lint/build chain before accepting a dependency change. npm proposes incompatible major downgrades for several roots, so no blind `audit fix --force` was applied. Closure requires a compatible lockfile update and a clean full-tree scan plus the full quality gate. This remains open and does not change NO-GO. See docs/quality/phase6/dependency-summary.json.
