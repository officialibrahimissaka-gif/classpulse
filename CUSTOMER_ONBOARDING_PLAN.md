# Customer onboarding plan

2 November 2026. Closed-pilot playbook; not an invitation to upload live data before release gates close. Economic buyer: UAE permanent-placement agency owner/operations head; champion: coordination lead; users: recruiters/account managers; external participant: explicitly authorized client contact. Candidate self-service is excluded.

## Qualification and agreement checklist

- [ ] Recurring accepted-placement handoff with a named accountable owner; confirm an existing ATS and show why competent native configuration does not solve the observed gap.
- [ ] Five-case/artifact discovery gate and named paid-evaluation commitments satisfied at portfolio level; no invented evidence.
- [ ] Approved security/privacy/legal/recovery/production release record, signed seller/data/processing/order terms, permitted customer and client access and staffed support contact.
- [ ] Agree one cohort, baseline, required fields/tasks, definition of ready/start and value/continuation decision; no claim of legal permission, permit approval or guaranteed start.
- [ ] Explain GHS billing by the Ghana seller, provider eligibility, accepted tax/invoice/payment/renewal/refund terms; verify an actual approved payment separately from entitlement grants.

## Assisted setup and activation

| Step / owner | Work | Acceptance / evidence |
|---|---|---|
| Buyer + owner | Verified provider login/MFA, company/entity/time zone/authority/retention attestation; set scoped roles | Correct tenant, nonowner negative test, named admin backup, recorded policy reference; attestation is not legal verification |
| Champion | Add one real authorized client and minimal candidate reference | No passport/medical/bank/permit files; data minimization review complete |
| Champion + implementation | Dry-run a redacted/safe CSV, resolve errors and quota limits, then commit an approved batch | Counts reconcile, duplicate source keys do not create duplicates; no whole ATS dump |
| Coordinator | Publish agreed checklist, enter accepted placement and assign internal owner | Original/agreed date preserved, mandatory tasks and blockers visible |
| Agency + client HR | Invite one authorized contact with explicit field/task allowlist | Identity matches invite, unrelated client/placement denied; expiry/revocation explained |
| Coordinator + manager | Complete or reviewed-waive tasks; resolve exceptions; human readiness then separate actual start | Complete lifecycle with historical transitions; no automatic employment decision |
| Manager | Reconcile four core KPIs, drill-downs and export formats | Source cohort and as-of/filter definitions understood; cross-format same-snapshot gap must close before full acceptance |
| Owner | Demonstrate module-off read/export/reactivation and subscription exit handling | No silent deletion or automatic replay of stopped effects |

Proposed activation event: within seven days of authorized account setup, the organization creates one placement with an owner, dated required task and at least one completed handoff. First value: the champion confirms the first usable owned handoff after comparing it with the prior process. Time-to-first-value is measured from completed setup to that confirmation; mark censored/nonactivated accounts, not zero. This event definition is a launch measurement design; a complete analytics event pipeline is not implemented.

## Pilot cadence and exit

Proposed four-week pilot starts only after signed scope and release gates. Day 0 record baseline/workload/expected starts; days 1–2 assisted setup; day 7 review activation and support effort; weekly inspect missed handoffs and counterexamples with lawful evidence; week 4 buyer reviews cohort outcomes and total effort. Extend only for an explicit reason (for example start dates beyond the cohort window), not to conceal poor activation. Pre-agree the evaluation fee and continuation decision; do not promise savings.

If successful, verify actual collected recurring payment/invoice, reviewed plan activation, support handoff and permission to use any quote/logo. If unsuccessful, record reasons, stop writes as agreed, provide authorized exports, revoke external access and follow reviewed retention/exit procedures; deletion/hold obligations are not replaced by canceling billing. No silent renewal during an evaluation.

## Feedback and support

Use a restricted feedback register: account/role, observed task, incident date, expected/actual outcome, safe artifact reference, severity, current workaround, frequency, effort/cost evidence, next owner and disposition. Separate request, defect, misunderstanding and out-of-scope regulated service. Security/privacy incidents use OPERATIONS_RUNBOOK immediately; never store sensitive raw records in a shared sales sheet. Review weekly with champion and fortnightly with buyer. Ask about recently completed work, not hypothetical feature preferences. Obtain explicit permission for interviews/recordings/case studies; none have been conducted here.
