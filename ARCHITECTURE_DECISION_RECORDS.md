# Architecture decision records

Recorded: 1 November 2026. Status: **selected design baseline, pending implementation and validation**. No ADR implies deployed infrastructure, legal approval or successful load/security tests. Relevant source and verification boundaries appear in SYSTEM_ARCHITECTURE.md and UAE_COMPLIANCE_RESEARCH.md.

| ADR | Decision / context | Alternatives considered | Consequences and reconsideration trigger | Trace |
|---|---|---|---|---|
| ADR-001 | Modular monolith, one release with web/API and worker processes | Microservices; single synchronous server | Fewer deployment/consistency problems; strong package boundaries required. Extract only for measured scaling, fault/residency or team ownership pressure | ARCH-001, MB-001; REQ-L001 |
| ADR-002 | Next.js + TypeScript for web and thin REST API adapters over server-only services | Next.js + NestJS; React SPA + Fastify; Django/.NET | One language/runtime and fewer components. Next.js caching/RSC boundaries need active security discipline. Separate API framework only if API ownership/runtime needs justify it | ARCH-002/003; REQ-P001–REQ-P003 |
| ADR-003 | PostgreSQL 17 managed Multi-AZ as authoritative store | MySQL, document DB, per-service DBs | Strong transactions/RLS and relational integrity; centralized bottleneck must be measured. No assumption that Multi-AZ equals backup or regional DR | ARCH-004; REQ-P006/P008 |
| ADR-004 | Shared tenant tables with FORCE RLS, composite tenant keys, application field/scope policy | Schema per tenant; database per tenant; filter-only ORM | Efficient initial operation; app compromise can still set tenant context. Dedicated-cell/database options later for justified isolation/residency, not a promise of physical isolation today | ARCH-004; REQ-P001/P003 |
| ADR-005 | Prisma for typed persistence plus reviewed SQL migrations | Drizzle/Kysely/raw SQL; Prisma schema alone | Familiar typed CRUD, migration tooling; RLS/roles/partial indexes require hand-reviewed SQL and real database tests. No root-client escape path or session-global tenant context | ARCH-004; REQ-P001/P006 |
| ADR-006 | Managed Cognito user pools in UAE cell; app-owned revocable sessions and permissions | Keycloak self-hosted; Auth0/Clerk; password handling in app | Less identity operations, regional endpoints verified. App still owns invites, tenant context and current authorization. Keycloak is a fallback only after a documented identity/residency requirement, not a second simultaneous IdP | SEC-002; REQ-P002 |
| ADR-007 | Typed in-process authorization and query predicates; no external policy service in R1 | OPA, OpenFGA, database-only RBAC, IdP group permissions | Easy transaction-bound decisions; requires policy test matrix and centrally enforced boundaries. Revisit when relationship cardinality or shared-service policy distribution warrants it | SEC-001/003; REQ-E001/E014 |
| ADR-008 | BullMQ + managed Redis-compatible engine; durable PostgreSQL job/outbox/inbox | SQS/EventBridge; pg-boss only; in-memory timers | Good TypeScript delayed-job ergonomics; extra Redis operations and at-least-once handling. PostgreSQL is recovery source. Revisit if queue throughput/operations cost favors native cloud queue | ARCH-005; REQ-P006/F038 |
| ADR-009 | No general authorization/data cache in R1; PostgreSQL authoritative revision checks | Redis-cached roles/entitlements; JWT-only access | Additional database reads preserve next-request revocation. Add cache only with demonstrated need and an authoritative revision/fencing mechanism | REQ-P002/E014 |
| ADR-010 | Private S3 + authenticated download proxy, seven-day artifacts | Public objects; standalone presigned links; database blobs | Proxy costs bandwidth/compute, but meets current revocation requirement. Presigned URLs cannot independently guarantee revoked-user denial for their remaining TTL | ARCH-006; REQ-R005/P009 |
| ADR-011 | PostgreSQL search and operational reporting, no warehouse/search cluster in R1 | OpenSearch, external SaaS BI, Snowflake/ClickHouse | Lower cost and fewer data copies; limited language ranking/large analysis. Revisit with measured Arabic search quality, query latency or analytics isolation needs | ARCH-002/006; REQ-R001/R009 |
| ADR-012 | Effective-dated pure jurisdiction adapters, disabled until reviewed | One UAE rules object; hard-coded payroll formulas; tenant arbitrary code | More explicit coverage/versioning; requires legal review, fixtures and updates per regime. Research findings never activate a payroll pack automatically | GLOB-003; REQ-F042/F043 |
| ADR-013 | Regional residency cells; entire tenant pinned to one home cell initially | Global active-active database; entity-by-entity writes from one tenant | Clearer data paths and privacy boundaries; a multi-entity tenant cannot choose conflicting per-entity residency settings in R1. Repartition only as a separately designed later capability | GLOB-004; REQ-P001/P005 |
| ADR-014 | Docker on ECS Fargate, regional managed DB/queue/storage; Terraform and GitHub OIDC | Kubernetes; single VM; global serverless frontend | Managed isolation/restarts and portable containers; baseline AWS/network cost. Avoid global runtime replication of private records. Move to Kubernetes only for real operational needs | DEP-001/002 |
| ADR-015 | Shared snapshot generator for PDF/CSV/XLSX; isolated PDFKit renderer | Client-side export; Playwright/Chromium HTML-to-PDF; unrelated format query paths | Structured PDF is sufficient for R1 cards/tables/vector charts and avoids a browser sandbox dependency on Fargate; layout takes more explicit code and Arabic/accessibility need tests. Library versions/licenses/security reviewed before implementation | ARCH-006; REQ-R002/R005/R006 |
| ADR-016 | Same-country backups and regional recovery initially; no automatic cross-border replica | Cross-region replication by default; no DR plan | Residency simpler; full region outage may exceed RTO. Obtain accepted risk or approved recovery region before contractual availability promises | DEP-004; REQ-P005/P008 |
| ADR-017 | English R1, Unicode/ICU and RTL-ready components from start | Hard-coded English schema; full translated/legal-content launch | Avoid expensive model rewrites without pretending translation is complete. Arabic launch needs native-speaker QA and separate legal-template review | GLOB-001; REQ-P007 |
| ADR-018 | Record explicit permissioned source/provenance, no automatic candidate/employee identity merge | Email-based identity merge; copied universal person object | More review work, fewer accidental privacy/scope expansions. Later identity resolution needs purpose-aware mappings and auditable consent/legal basis | MB-002; REQ-P011/F004 |

ADR changes need context, date, owner, affected requirement/test IDs, migration/rollback, residency/security impact and superseded record link. Keep historical IDs; do not overwrite a decision to conceal a trade-off. Engine, package and cloud-service patches must be pinned and validated at implementation; this design does not select an unmaintained version for the sake of matching a document.
