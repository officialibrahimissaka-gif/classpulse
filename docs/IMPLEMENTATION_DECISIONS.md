# Phase 5 implementation decisions

- **IMP-R1-ADR-001 — deploy a closed schema subset.** Keep the 165-model full vision intact and deploy the 56-model R1 FK closure, with tracked companion SQL. New mutable report-run/invitation-delivery/commercial-request state is separate from immutable snapshots/history. TeamMembership makes team saved views explicit rather than inferring membership from role/email.
- **IMP-R1-ADR-002 — serialize initial tenant writes.** Business mutations acquire a tenant row update lock; reads and bounded dispatch/download attempts share the module fence. This trades write concurrency for straightforward quota/module/scope correctness at pilot scale. Revisit only with load evidence and race tests.
- **IMP-R1-ADR-003 — real local adapters, fail-closed production.** Native PostgreSQL/Redis, SMTP Mailpit and private encrypted staging/local artifacts support reproducible development. Production paths use OIDC/Cognito, SES and S3, with no fabricated success. External bindings and provider MFA assumptions remain release checks.
- **IMP-R1-ADR-004 — no production payroll.** There is no calculation engine, payroll module, legal pack activation or government submission endpoint. Jurisdiction/entity configuration is an attested context only.
- **IMP-R1-ADR-005 — deterministic source identity.** Candidate source keys and placement source keys are separate. Imports never merge by email; conflicts roll back. Reopening starts a new coordination cycle while preserving the original plan and prior transitions unless a reviewed privacy erasure requires removal.
- **IMP-R1-ADR-006 — snapshots, not mutable historical reports.** Server KPI definitions/version hashes bind immutable source projections; UI/export share formulas and source membership. Job progress lives separately. Current policy changes invalidate artifacts; new exports remain possible from read-only retained sources in the exit window.
- **IMP-R1-ADR-007 — bounded OOXML instead of ExcelJS.** Replace vulnerable transitive spreadsheet dependencies with fflate packaging of literal OOXML cells. Test with an independent XLSX reader, including formulas-as-text and Arabic names. This supports the required simple tabular exports without a general spreadsheet engine.
- **IMP-R1-ADR-008 — separate reviewed maintenance.** Runtime has no physical source deletion and cannot assume retention privileges. Maintenance gets explicit column/table rights, no dispatcher-directory membership, and an explicit tenant input. A durable manifest supports storage retry. Automatic approval review rejected broader grants; the final migrations use the narrower alternative.
- **IMP-R1-ADR-009 — reviewed commercial operations.** Customer plan requests do not self-grant paid access. A separate controlled operator verifies an accepted order and atomically updates subscription/capacity at a reviewed effective time. Downgrades preserve excess data; cancellation has a 30-day read/export window. Payment-provider automation is excluded.

These choices implement the authorized Phase 5 scope; they do not approve production release, legal rules, customer validation or external infrastructure claims.
