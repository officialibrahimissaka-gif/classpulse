# Implemented internal API

The R1 contract is [api/r1.openapi.yaml](../api/r1.openapi.yaml), generated by `scripts/api-contract.ts` and validated with Swagger Parser. It documents 37 implemented versioned operations. Root `openapi.yaml` remains the full Phase 3 vision and must not be advertised as deployed functionality.

All versioned data operations use HttpOnly tenant sessions and current server authorization. Mutations require exact Origin, CSRF and 16–160-character idempotency keys; registration instead uses a short-lived sealed verified identity and nonce-bound atomic provisioning. Placement actions, shared task completion and task assignment require `If-Match: "vN"`. List clients/placements with `limit` 1–100 and an optional exclusive UUID `after` cursor; ordering is by ID, so the next cursor is the last returned ID. The UI collects pages and sorts placement dates for presentation. Other bounded administrative lists are not a public API or bulk data-extraction contract.

Error bodies contain type/title/status/code/requestId and optional field/code issues; no raw values or database/provider errors. Expected states include 401 access/session changes, 403 scope/module/MFA/CSRF denial, 409 quota/idempotency/dependency/state conflicts, 412 stale version, 413 body limit, 422 validation/report-range errors, 428 missing version and 429 throttling. Module and scope checks also run on retries and downloads. No public bearer keys or webhooks are enabled in R1.

Additional identity adapters:

| Route | Contract |
|---|---|
| GET /api/auth/login | OIDC PKCE/state/nonce redirect; optional validated workspace slug for fresh reauthentication; returns 303 and short-lived sealed flow cookie |
| GET /api/auth/callback | Validates provider code/state/nonce/verified email; issues sealed identity, and a new workspace session only after current membership checks when reauthenticating |
| POST /api/auth/development | Local development only; strict `{name,email}`; explicitly unverified and never MFA-qualified; 200 `{ok:true}` + identity cookie |
| POST /api/auth/workspace | Strict `{slug}` plus sealed identity and exact Origin; current issuer/subject membership required; 200 `{ok:true}` + session cookie |
| POST /api/auth/logout | Session, Origin and CSRF; revokes durable session and clears cookie; 200 `{ok:true}` |
| POST /api/invitation | Strict `{action:"remember",context:{tenantId,invitationId,secret}}` stores an encrypted short-lived intent cookie after the browser removes the URL fragment; `{action:"accept"}` validates the verified identity, token/hash/expiry/inviter/current scopes before a session is issued |
| GET /api/health | 200 ready only when PostgreSQL and Redis respond; otherwise 503 unavailable; no infrastructure details |

Invite secrets never enter URL paths/queries or queue payloads. The client portal receives an explicit projection; missing optional shared fields are omitted, not merely hidden. Artifact responses are authenticated binary attachment downloads, no-store, with current authorization/content-integrity checks. A client cannot obtain internal placement detail or a report export by guessing IDs.

Report dates are inclusive calendar bounds; conceptually the `to` day ends at the next day’s exclusive boundary. Metric denominators and drill-down membership are calculated centrally. Source queries include selected original/actual-date cohorts plus current nonterminal work, subject to current permissions and selected client/entity. Limit a request to at most 10,000 relevant source rows; narrow the filter if exceeded. Generated artifacts are capped at 5,000 source rows by REQ-P008; narrow filters if a report exceeds that export cap. No prior-period comparison is fabricated where historical snapshots do not exist.

Phase 6: privileged participant reads and revocation enforce participants.manage record scope as well as role presence; entity-scoped creation/import commands enforce their write scope. Validation errors consistently use no-store application/problem+json.
